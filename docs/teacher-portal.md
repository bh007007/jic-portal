# 강사 포털 (LMS, `apps/teacher`)

JIC 포털 4개 포털 중 네 번째다(`docs/architecture.md`). 11/8 사용자 결정에 따라 **LMS = 강사 포털**이고, 이 저장소에서 만든다. 기준은 메뉴 검토표 'LMS' 시트와 원칙 L1~L10이다.

- **쓰는 사람**: 강사·체커·스케줄러·매니저(역할 `user_roles`), 그리고 직원(관리자 포털 계정)이다. 화면별 권한은 `docs/roles.md`(11/9 승인): 성적·자료는 강사·매니저·관리자, 관리는 매니저·관리자, 오피스 직원은 읽기만.
- **화면**: 휴대폰 기준이다(원칙 L7). 아래쪽 메뉴는 홈·학생·성적·자료실·더보기 5개다.
- **언어**: 한국어와 영어다(필리핀 강사). 브라우저 언어가 한국어면 한국어, 아니면 영어로 시작하고 위쪽 버튼으로 바꾼다. 문구는 `src/i18n.tsx` 한 곳에 있고 한국어가 기준이다.
- **주소**: JIC 포털 아래 `/teacher/`다. 관리자 포털·인트라넷과 같은 주소라 직원은 한 번 로그인으로 오간다(원칙 C6).
- **서버 코드**: 없다. 화면이 Supabase를 바로 부르고 권한은 RLS가 막는다. 강사용 학생 목록만 DB 함수(`lms_students`)로 받는다.

**준비 중**(더보기에 이유와 함께 표시, 원칙 C8):
- **반복 시간표가 필요함**(원칙 V1·V6): 수업 변경·옵션 클래스, 반복 규칙(요일·기간) 시간표. 지금은 '수업 관리'에서 하루를 만들고 다음 날들로 복사한다(11/9).
- **결석 신청 승인**: 지금은 인트라넷에서 한다(L4, 같은 DB 함수를 쓰게 할 예정).
- **결정이 필요함**: 그로스 리포트·Daily Recall(L10), 녹음(L9 보관 기간).

## 출석 (`supabase/migrations/20261109000000_attendance.sql`, 11/9)

단위는 업체 정규 출석과 같다: 한 수업(날짜·시각·교사·교실) × 학생 한 명. 업체는 시간표에서 그날 출석 행을 만들고 교사가 결과를 고친 뒤 캠퍼스·날짜별로 마감한다. 여기서도 수업과 출석 행을 미리 만들고 결과는 비워 둔다.

| 테이블 | 뜻 | 읽기 | 쓰기 |
| --- | --- | --- | --- |
| `classrooms` | 교실(캠퍼스·번호·1:1/그룹·건물·층·정원, 업체 `cro_id`) | 강사 포털 사용자 | 매니저·직원·스케줄러 |
| `class_sessions` | 그날 한 시간대의 수업(시각·분·캠퍼스·종류·과목·강사·보조 강사·교실) | 강사 포털 사용자, 학생은 자기가 든 수업 | 매니저·직원·스케줄러(마감된 날은 못 고침) |
| `attendance` | 수업 × 학생: 결과(AT·AB·TA, 비면 미체크)·지각 분·사유 인정·메모, 체크한 사람·시각(서버가 넣음), 업체 `sta_id` | 강사 포털 사용자, 학생 본인 | 결과: 그 수업 강사·보조 강사, 체커, 매니저·직원. 사유 인정: 매니저·직원. 행 넣기·지우기: 매니저·직원·스케줄러 |
| `attendance_closings` | 캠퍼스·날짜 마감(마감한 사람은 서버가 넣음) | 강사 포털 사용자 | 매니저·직원(오늘까지만) |

규칙(트리거 `attendance_guard`): 마감된 날은 아무도 못 고친다(서비스 키로 옮겨 넣을 때만 예외). 앞날 수업은 결과를 못 넣는다. 지각이 아니면 지각 분을 지운다.

함수:
- `lms_sessions(날짜, 캠퍼스)`: 그날 수업 목록, 강사 부르는 이름·교실·학생 수·체크 수·결석·지각, 내 수업인지, 마감인지.
- `attendance_mark_all(수업)`: 미체크 학생을 모두 출석으로. 권한·마감은 표의 RLS·트리거가 그대로 막는다.
- `can_mark_attendance(수업)`: 출석 입력자 판단. 결정 #5가 바뀌면 이 함수만 고친다.
- `current_lms_name()`: 기록자 이름. 강사 목록 이름 → 직원 이름 → 로그인 이메일 → 계정 id.
- `lms_copy_sessions(원래 날, 날짜[], 캠퍼스)`(`20261109090000_schedule_copy.sql`): 하루 수업을 다른 날로 복사. security invoker라 권한은 출석 표 RLS(can_schedule)가 막는다. 휴일·마감된 날·같은 날·시각·캠퍼스·강사·교실 수업은 건너뛰고, 그날 재학생(lms_students)만 옮긴다. 한 번에 31일까지.
- `lms_attendance_summary(시작, 끝, 캠퍼스)`·`lms_student_attendance(학생, 시작, 끝)`(`20261109080000_attendance_summary.sql`): 출석 확인 화면용. 결석 사유는 사유 인정 / 그날 승인된 결석 신청 / 무단(인트라넷 무단결석 패널티 후보와 같은 기준). 신청의 교시와 수업 시각은 아직 맞추지 않는다. 사유 글은 주지 않는다. 기간 92일 안.

권한 시험은 `supabase/tests/attendance_rls.mjs`(79개)이고 CI가 돌린다.

### 업체 출석 구조 (11/9 LMS 조사, 값 없이 구조만)

- **정규 출석** `adm/attendance_v2/regular`:
  - `regular_sched_load`(`s_the_date`, `s_sta_ca_id`)가 그날 시간대(`s_time`, 건수)와 마감 여부(`close_yn`)를 준다.
  - `sel_time=HH:MM`을 넣어 `regular_load`를 부르면 출석 행(`sta_*`)이 온다.
  - 출석 행의 열:
    - 연결: `sta_st_id`(학생 `st_id`, 연수 아님), `sta_te_id`·`sta_sub_te_id`(교사), `sta_cro_id`(교실).
    - 수업: `sta_date`·`sta_time`·`sta_min`, `sta_type`(1 / G), `sta_subject`.
    - 결과: `sta_result`(AT / AB / TA), `sta_late_min`, `sta_excused`(Y / N).
- **캠퍼스**: 번호 11·12·14. 11/6·10/30 출석 기록은 캠퍼스 12에만 있다.
- **마감**: `closing_load`(`sac_*`: 캠퍼스·날짜·종류·마감 여부), 달 단위.
- **교사·교실**: 교사 `adm/teacher/regist_load`(`te_*`), 교실 `adm/classroom/classroom_v2_load`(`cro_*`: 1:1 / G, 담당 교사, 옵션·셀프·주말).
- **그 밖**: 옵션클래스 `ocl_*`, 셀프스터디 `sfs_*`, 시험 `exm_*`. 교시별 시간표는 `schedule_detail` 쪽으로 보이는데, `_load`가 아니라 부르지 않았다.
- **주의**: 교사·출석 응답에 교사 비밀번호(`te_pw`)·급여(`te_salary_*`)가, 일별·기간 응답에 계좌(`am_acct_*`·`ag_acct_*`)가 섞여 온다. 추출 스크립트 `scripts/extract/portal-extract-attendance.js`는 열 허용 목록에 있는 열만 저장한다.

### 로컬에서 보기

로컬 시험 서버(`pg-supabase.mjs`)에 가짜 교실·수업·출석 행을 SQL로 넣고 강사 계정·매니저 계정으로 확인했다(11/9).
- 강사: 오늘 내 수업 2개, 학생별 체크, 지각 분, 모두 출석, 남의 수업은 보기만.
- 매니저: 캠퍼스 마감·되돌리기, 사유 인정.

## 강사 계정 만들기 (관리자 포털 '사용자·권한' 화면이 생길 때까지)

1. Supabase → Authentication → Users → **Add user**: 이메일, 비밀번호, Auto Confirm.
2. SQL Editor에서 역할과 강사 목록을 잇는다.

   ```sql
   insert into public.user_roles (user_id, role) values ('<사용자 id>', 'teacher') on conflict do nothing;
   insert into public.staff (user_id, name, nickname, campus) values ('<사용자 id>', '이름', 'Teacher …', 'Premium');
   ```

   역할은 `teacher`·`checker`·`scheduler`·`manager` 중에서 고른다. 매니저는 시험 종류·강사 목록을 관리한다. 관리자 포털 직원(`staff_users`)은 역할 없이도 강사 포털을 쓴다.

## 실행

- **로컬**: `apps/teacher/.env.example` → `.env.local`, `npm run teacher` → http://127.0.0.1:5178. 데이터는 Supabase에 있다.
- **로컬 시험 서버로 화면 보기**:
  - `node supabase/tests/pg-supabase.mjs 54321`(가짜 Supabase, 샘플 데이터)로 띄운다.
  - `VITE_SUPABASE_URL=http://127.0.0.1:54321 VITE_SUPABASE_ANON_KEY=anon-key npm run teacher`로 실행한다.
  - 시험 계정은 `/__user`·`/__sql`로 만든다. 11/8에 이 방식으로 로그인·홈·학생·성적 입력·자료 추가를 확인했다.
- **검증**: `npm run teacher:build`.
- **배포**: Cloudflare Pages 빌드 명령 끝에 `npm run teacher:portal`을 붙인다. 11/8에 `npm run portal:build && npm run teacher:portal --if-present`로 바꿔 두었다(머지 전에도 깨지지 않게 `--if-present`).
  - 출력은 `apps/admin/dist/teacher`다.
  - `functions/teacher/[[path]].ts`가 `/teacher/…` 화면 주소에 강사 포털 `index.html`을 준다.
