# 인트라넷 (`apps/intranet`)

직원용 화면과 경비실 가드 태블릿이다. 디자인은 `docs/design/IntranetPenalty.dc.html`(I1 패널티 승인)과 `GuardTablet.dc.html`(I2 외출·귀가 가드 태블릿, 1180×820)을 따른다. 로컬 개발 서버로 개발하고, 배포는 Cloudflare Workers 하나로 한다(아래 '배포', 직원 화면·가드 태블릿 서버 코드 11/8, Cloudflare 설정 전).

## 실행

```powershell
npm install
npm run intranet
```

http://127.0.0.1:5177 을 연다. 가드 태블릿은 http://127.0.0.1:5177/guard (외출·귀가 화면의 '가드 태블릿 열기'). 로컬에는 로그인이 없다(관리자 앱과 같다).

## 규칙

### 외출·귀가 (가드 태블릿)

- 재학생 명단(관리자 core의 '재학' 분류)에 있는 학생만 기록한다. 졸업생·입학 예정자는 "재학생 명단에 없는 번호입니다."
- 입력값에서 숫자만 쓴다. USB·블루투스 QR 스캐너가 카드키 QR을 읽어 학생번호 칸에 넣고 Enter를 보내면 바로 처리된다. 학생번호 칸에는 항상 커서가 있다.
- 외출: 이미 외출 중이면 거절한다(외출 시각을 보여 주고 귀가로 처리하라고 안내).
- 귀가: 외출 기록이 없어도 귀가는 남긴다. 통금 확인에 필요하기 때문이며, 목록에 '외출 기록 없음'으로 보인다.
- 설정에 근무자가 있으면 근무자를 골라야 기록된다. 이 기기에서 고른 캠퍼스·근무자·외출/귀가는 기기에 기억한다.

### 통금 판정

- 시각은 필리핀 시간(UTC+8) 기준이다. 저장은 ISO(UTC).
- 외출·귀가는 '밤' 단위로 묶는다. **오전 5시 전 기록은 전날 밤**이다(예: 11/8 01:10 귀가 → 11/7 밤).
- **승인된 외박이 있는 밤은 통금 위반이 아니다.** 외출 기록과 가드 태블릿에 '외박 허용 ~복귀일'로 보인다. 1박 이상 학교 여행에 참가 신청한 학생도 같다('외박 허용 ~돌아오는 날 (학교 여행)').
- 그 밖에 그날 밤 통금 시각(설정, 처음 값 23:00)보다 늦게 외출했거나, 늦게 귀가했거나, 통금이 지나도 귀가하지 않았으면 통금 위반이다. 근거 문장 예: `통금 23:00, 귀가 23:41`, `통금 23:00 이후 외출 23:20, 귀가 23:55`, `통금 23:00, 미귀가`, `통금 23:00, 귀가 01:30 (외출 기록 없음)`.

### 공항 이동 배차 (귀국 일정)

- 학생이 귀국 항공편에서 '공항 이동 차량 요청'을 하면 '요청'으로 보인다. '처리'에서 **배차 확정**(기숙사 출발: 출발일 또는 전날 + 시각, 메모: 차량·집합 장소) 또는 **배차 불가**(사유 필수)로 처리한다. 메모는 학생 앱에 보인다.
- 기숙사 출발이 비행기 출발보다 늦으면 거절한다. 처리자(오른쪽 위 직원 이름)와 시각이 남고, 다시 처리하면 덮어쓴다. 출발일이 지난 항공편은 처리하지 않는다.
- 처리 뒤 학생이 출발일·시각을 바꾸면 **재확인 필요**, 차량 요청을 빼면 **요청 취소**로 보인다. 메뉴의 숫자는 오늘 이후 출발 중 요청·재확인 건수.
- 배차 기록(직원이 씀)과 항공편(학생이 씀)은 따로 저장한다(기획안 C2). 모양과 규칙은 `apps/student/server/departures.ts`.

### 가드 리포트 (업체 eni, 기획안 incident_reports)

- 가드 태블릿의 '사건 리포트 작성'에서 학생번호(방금 처리한 학생이 미리 들어감), 종류, 내용(500자), 발생 시각(비우면 지금)을 받는다. 종류는 업체 포털과 같은 음주·폭력·무단외출·기타.
- 발생 시각이 지금보다 뒤면 전날로 본다(자정 넘어 쓰는 리포트). 재학생만, 설정에 근무자가 있으면 근무자를 골라야 등록된다.
- 등록하면 **패널티 승인 대기 후보가 바로 생긴다**(출처: 가드 리포트). 음주는 '음주', 폭력·무단외출·기타는 '기타'로 들어간다(점수표에 따로 없는 종류). 근거는 `가드 리포트(22:40): 음주 — 내용 앞 60자`, 발생일은 통금과 같은 '밤' 기준.
- 리포트는 고치거나 지우지 않는다. 잘못 쓴 리포트는 패널티를 반려한다(통금 후보 정리는 가드 리포트 패널티를 건드리지 않는다).

### 학교 여행 (업체 'Outing > Travel'의 tra 여행 / trt 신청자)

- 직원이 여행을 올리고 학생이 학생 앱에서 참가 신청·취소한다. 모양과 규칙은 `apps/student/server/trips.ts` 한 곳이다.
- 등록: 제목·장소 필수(100자), 집합(100자)·안내(1000자) 선택. 새 여행은 출발일이 오늘 이후, 돌아오는 날은 출발일과 같거나 뒤(14박까지), 신청 마감일은 출발일과 같거나 앞, 정원 1~500명, 비용 0 이상(PHP, 0 = 무료). 대상 캠퍼스를 비우면 전체 캠퍼스.
- 수정: 지난 여행도 고칠 수 있다(기록 정리). 정원은 이미 신청한 학생 수보다 줄일 수 없다. 취소한 여행은 고치거나 되돌리지 않는다(학생 앱에 '여행 취소'로 보인다).
- 상태: 신청 받는 중 ↔ 신청 마감(직원이 일찍 닫음), 여행 취소. 신청 마감일이 지나면 상태와 상관없이 학생은 신청·취소하지 못한다.
- 명단에서 빼기: 참가 신청만, 사유 필수(300자, 학생에게 보인다). 처리자는 로컬은 오른쪽 위 이름, 배포는 로그인한 직원. 다시 넣으려면 학생이 다시 신청한다.
- **외박 허용**: 1박 이상 여행의 참가 신청은 승인된 외박과 같이 본다(출발일 밤 ~ 돌아오는 날 전날 밤). 통금 확인·가드 태블릿·Student File·홈의 '오늘 밤 외박'에 들어가고, 신청 처리의 외박 목록에는 들어가지 않는다. 학생 취소·명단 제외·여행 취소·날짜 변경은 통금 위반 후보에 바로 반영한다.

### 생활 요청 (업체 '요청사항(학생)'·'ID 카드 교체', 기획안 nonacademic_requests)

- 학생 앱이 쓰는 요청 데이터를 그대로 읽고 처리한다. 모양과 규칙은 `apps/student/server/lifeRequests.ts` 한 곳이다.
- 접수 → 처리 중 → 완료·반려. 끝난 요청(완료·반려·학생 취소)은 바꾸지 않는다. 반려는 답변에 사유를 적어야 한다. 답변을 비우고 완료하면 지난 답변이 그대로 남는다.
- 처리할 목록(접수·처리 중)은 오래된 순, 끝난 목록은 최근 처리 순이다. 메뉴·홈에 접수 건수가 보이고, Student File에 그 학생의 요청이 보인다.
- 처리자는 로컬은 오른쪽 위에 입력한 이름(없으면 비워 둠), 배포는 로그인한 직원이다.

### 신청 처리 (결석·외박)

- 학생 앱이 쓰는 신청 데이터를 그대로 읽고 고친다. 모양과 규칙은 `apps/student/server/requests.ts` 한 곳이다.
- 대기 중인 신청만 승인·반려된다. 학생이 이미 취소한 건은 건너뛰고 몇 건을 건너뛰었는지 알려 준다.
- 처리 메모(300자)는 학생 앱 신청 상세에 '담당자 메모'로 보인다. 반려 사유를 적는다.
- 대기 목록은 날짜가 가까운 순(처리할 순서), 처리된 목록은 최근 처리 순이다. 메뉴에 대기 건수가 보인다.

### 내부 공지 (기획안 I10, 업체 게시판 → 내부 공지)

- 대상은 전체 또는 캠퍼스 하나. 캠퍼스로 보면 그 캠퍼스 공지와 전체 공지가 함께 보인다.
- 게시 종료일이 지나면 '지난 공지'로 넘어간다. 수정에서 종료일을 지난 날로 바꾸면 바로 내려간다. 삭제 기능은 두지 않았다.
- 직원이 공지를 열면 읽음(이름·시각)이 직원마다 한 번 남는다. 이름을 입력하지 않았으면 읽음이 남지 않는다. 메뉴와 홈에 이 직원이 안 읽은 게시 중 공지 수가 보인다.
- 작성·수정에는 오른쪽 위 직원 이름이 필요하다(상담 기록과 같다).

### 상담 기록·접근 기록 (기획안 I5, 권한·보안 '접근 기록')

- 목록·Student File·접근 기록에는 **제목만** 내보낸다. 내용은 상세에서만 보이고, 상세를 열 때마다 '열람'을 남긴다. 같은 직원이 같은 기록을 10초 안에 다시 열면(새로고침 등) 한 번으로 센다.
- 작성·수정·후속 조치 완료·되돌림도 남긴다. 접근 기록은 추가만 되고 고치거나 지울 수 없다. 상담 기록 삭제 기능은 두지 않았다.
- 검색은 학생·제목·작성자만 된다. 내용 검색은 사실상 열람이라 넣지 않았다.
- 후속 조치 기한이 있으면 '확인할 일'에 들어가고, 기한이 지나면 빨갛게 보인다. 메뉴에는 기한이 오늘이거나 지난 건수, 홈에는 열린 건수가 보인다. 기한을 바꾸면 다시 열린 상태가 된다.
- 처리자: 로컬에는 로그인이 없어 **오른쪽 위에 입력한 직원 이름**(브라우저에 저장)을 쓴다. 이름이 없으면 상담 기록을 열거나 쓸 수 없다. 배포에서는 로그인한 직원으로 바꾼다.
- 상담 분류(학업·생활 등)와 공개 범위는 정해지지 않아 만들지 않았다. 제목에 자유롭게 쓴다.

### 패널티

- 통금 위반은 외출 기록에서 **승인 대기 후보로 자동으로 올라간다**(출처: 외출 기록). 같은 외출 기록으로는 한 건만 생긴다.
- 승인 대기 중인 후보는 다시 계산한다. 미귀가였다가 귀가하면 근거가 바뀌고, 통금 시각을 늦추거나 그 밤의 외박을 승인해 더는 위반이 아니면 후보에서 빠진다. 승인·반려한 건은 바뀌지 않는다.
- 점수는 점수표에서 가져온다. **비어 있으면 '점수 미정'**으로 보이고, 그대로 승인하면 0점으로 센다. 승인할 때의 점수를 그 건에 남기므로, 나중에 점수표를 바꿔도 이미 승인한 점수는 그대로다.
- '승인 후 누적'은 그 학생의 승인된 점수 합계 + 이 건의 점수, 경고 단계는 점수표 기준으로 `- → 1단계`처럼 바뀌는 단계를 보여 준다. 기준이 비어 있으면 '기준 미정'.
- 위반 종류는 디자인의 4가지(무단결석, 통금 위반, 음주, 기타)다. 통금 위반은 외출 기록에서, 음주·기타는 가드 리포트에서 후보가 생긴다. 무단결석은 LMS 출석이 연결된 뒤 붙인다.

- 학생·연수는 관리자 앱의 `createDb`(재학생 명단 `listEnrollments`, 이름 `studentDetail`)와 `loadDir`을 그대로 쓴다.
- 스타일은 관리자 앱과 같은 값을 `src/styles.css`에 복사해 두었다(공통 UI 패키지가 생기면 옮긴다).
- 시험: `npm --workspace apps/intranet run test`. 통금 판정 경계(통금 후 외출, 자정 넘어 귀가, 외출 기록 없는 귀가, 미귀가 후 귀가), 점수표 검증, 승인 점수 유지, 통금 변경 시 후보 정리, 외박 승인 시 후보 제외·외박 허용 표시, 결석·외박 승인·반려와 메모, Student File 목록·상세, 상담 기록(처리자 필수, 목록에 내용 없음, 내용 검색 안 됨, 열람 기록·10초 중복 제외, 수정·후속 조치, 필리핀 날짜 검색), 내부 공지(고정 순서, 캠퍼스 대상, 읽음 직원마다 1번, 안 읽은 수, 게시 종료), 가드 리포트(검증, 자정 넘은 발생 시각, 패널티 후보·종류 연결, 목록 검색), 귀국 일정(기본 기간, 미등록, 차량 요청), 공항 이동 배차(직원 이름 필수, 처리할 것, 확정·불가, 항공편 변경 시 재확인) 등 117개 항목.

## 배포 (JIC 포털 주소 아래 /intranet)

인트라넷은 **JIC 포털(관리자 앱) Cloudflare Pages 프로젝트 안 `/intranet/`**에 올린다(11/8 결정: 포털과 같이 쓰고, 한 번 로그인으로 오간다. Cloudflare·GitHub·Supabase는 지금 쓰는 계정 하나로). 직원 화면과 가드 태블릿(출입구 공용 계정)을 같은 주소에서 쓰고, 로그인한 계정 종류로 나뉜다.

- **빌드**: `npm run portal:build` = 관리자 앱 빌드 + 인트라넷을 `--base /intranet/`로 빌드해 `apps/admin/dist/intranet`에 넣는다(`apps/intranet` 의 `build:portal`).
- **화면 주소**: `functions/intranet/[[path]].ts`가 `/intranet/…` 화면 주소에 인트라넷 `index.html`을 준다(새로 고침·바로 열기). 파일(`/intranet/assets/…`)은 그대로.
- **API**: `/intranet/api/*` = `functions/intranet/api/[[path]].ts`가 인트라넷 서버(`apps/intranet/worker/index.ts`의 `handleApi`)를 그대로 부른다. 관리자 앱의 `/api/*`(`functions/api`)와 따로 돈다. 화면은 `src/base.ts`로 주소 앞에 `/intranet`을 붙인다.
- **한 번 로그인**: 같은 주소라 관리자 앱과 같은 로그인 저장 키(Supabase 기본값)를 쓴다. 한쪽에서 로그인·로그아웃하면 다른 쪽도 같다. 관리자 앱 위쪽 **인트라넷** 버튼 → `/intranet/`, 인트라넷 **통합관리** 버튼 → `/`.
- 로컬 개발은 그대로 따로 띄운다(관리자 5173, 인트라넷 5177, 버튼은 서로의 개발 서버로). Workers 단독 배포 설정(`apps/intranet/wrangler.jsonc`)도 남아 있지만 쓰지 않는다.

- **로그인**: 이메일·비밀번호(Supabase 계정). `staff_users`에 있으면 직원, `guard_accounts`에 있으면 가드, 둘 다 아니면 안내만 보인다.
  - 직원: 관리자 앱과 같은 계정. 처리자 이름은 `staff_users.name`이고, 오른쪽 위 이름 입력 칸 대신 로그인한 이름과 로그아웃이 보인다. 가드 주소(`/guard`)는 '가드 계정으로 로그인' 안내만 보인다(직원 계정으로 외출·귀가를 기록하지 않는다).
  - 가드(출입구 공용 계정, 11/8 결정): 어느 주소로 들어와도 가드 태블릿만 보인다. 캠퍼스는 계정의 출입구로 고정되고(화면이 보낸 값은 서버가 바꿔 씀), 기록에는 근무자 이름을 고른다(설정의 근무자 목록). 가드가 부를 수 있는 API는 `/meta`, `/guard`, `/guard/scan`, `/guard/report`뿐이다(나머지 `403 guard_forbidden`).
- **학생·연수**: 업체 원본(`legacy_*`, 직원만 읽기)을 읽는다(`server/supabaseData.ts`: 메타, 학생, 연수, 기숙사 배정). 직원 요청은 직원 토큰으로(관리자 앱 `functions/api`와 같은 방식), 가드 요청은 가드가 원본을 못 읽으므로 **서비스 키**로 읽는다. 가드에게는 가드 API의 응답(재학 여부·이름·캠퍼스·외출 기록)으로만 나간다. 같은 Worker 안에서 60초 기억한다.
- **가드의 승인된 외박**: 가드 화면의 '외박 허용 ~복귀일'과 통금 판정에 쓰는 승인된 외박만 서비스 키로 읽는다(`approvedOvernights`, 사유·담당자 메모·처리자는 읽지 않음). 학교 여행은 가드 토큰으로 읽는다(RLS: 여행과 참가 신청(applied)만, 제외 사유는 안 보임). 외출·귀가, 가드 리포트, 패널티 후보 쓰기는 가드 토큰으로 해서 RLS가 출입구 범위를 막는다.
- **통금 위반 후보**: 가드의 귀가 기록에서는 만들지 않는다(가드 권한 밖). 직원이 홈·패널티·외출 화면을 열 때 정리한다(로컬과 같음). 통금 직후 자동으로 만드는 크론은 남은 일.
- **저장소**: Supabase 테이블을 직원 토큰으로 읽고 쓴다(`server/supabaseStores.ts`, RLS). 계산은 로컬과 같은 core.
  - 결석·외박 승인·반려는 `decide_*` 함수, 배차·패널티 처리자는 로그인한 직원 id로 남기고, 화면에는 `staff_directory()`로 이름을 보인다.
  - 상담 기록은 테이블을 직접 못 읽으므로 `counseling.ts`의 `stores.remote`로 DB 함수(`counseling_open/create/update/followup`)를 쓴다. 목록은 `counseling_list()`(내용 없음, 맡은 캠퍼스만), 접근 기록은 DB 함수가 남긴다. 맡지 않은 캠퍼스 학생의 상담은 쓸 수 없다(`campus_not_allowed`).
  - 설정(통금·근무자)은 `intranet_settings` 한 행, 점수표는 `penalty_rules`·`penalty_stages`(종류·단계는 고정, 점수·기준만 바꿈).

### 설정 순서 (레오 PC의 Claude, 지금 쓰는 Cloudflare·Supabase 계정)

1. Supabase에 마이그레이션 `20261108100000_student_intranet.sql`, `20261108120000_student_request_ids.sql`, `20261108130000_intranet_deploy.sql`, `20261108140000_nonacademic_requests.sql`(생활 요청), `20261108150000_overnight_travel.sql`(외박·여행 정보), `20261108160000_school_trips.sql`(학교 여행)을 차례로 적용한다.
2. 직원 계정은 관리자 앱과 같다(`staff_users`, `docs/setup-cloud.md` 1-4). 이름(`staff_users.name`)을 넣어 둔다(처리자·접근 기록에 남는다). 상담 기록을 볼 직원은 `staff_campuses`에 맡은 캠퍼스를 넣는다(예: `insert into staff_campuses values ('<user_id>', 'Challenger')`).
3. 이미 있는 JIC 포털 Pages 프로젝트(`docs/setup-cloud.md` 2)의 **Settings → Build** 에서 Build command 를 `npm run admin:build` → **`npm run portal:build`** 로 바꾼다(출력 폴더 `apps/admin/dist` 는 그대로). 새 프로젝트는 만들지 않는다.
4. 같은 프로젝트의 **Settings → Variables and Secrets** 에 **Secret** `SUPABASE_SERVICE_ROLE_KEY` 하나를 더한다(Production). 가드 태블릿 요청(재학생 명단·승인된 외박)에서만 쓰고, 없으면 가드 요청만 `500 server_config`(직원 화면은 동작). Supabase 주소·anon 키는 관리자 앱이 쓰는 `VITE_SUPABASE_URL`·`VITE_SUPABASE_ANON_KEY` 를 그대로 쓴다.
5. 다시 배포한 뒤 JIC 포털 주소에서 직원 계정으로 로그인 → 위쪽 **인트라넷** 버튼 → 다시 로그인하지 않고 인트라넷 홈이 보이면 된다. 경비실 태블릿은 `<포털 주소>/intranet/guard` 에서 가드 계정으로 로그인해 둔다.
6. **가드 공용 계정**(출입구마다 하나): Supabase **Authentication → Users → Add user**(이메일 예: `gate-challenger@…`, 비밀번호, Auto Confirm 켜기)로 만든 뒤 SQL Editor에서 출입구를 잇는다.

   ```sql
   insert into public.guard_accounts (user_id, campus, label)
   values ('<만든 사용자 id>', 'Challenger', 'Challenger 정문')
   on conflict (user_id) do update set campus = excluded.campus, label = excluded.label;
   ```

   캠퍼스 이름은 관리자 앱의 캠퍼스 표시와 같게 쓴다(`Challenger`, `Premium`, `MCO`). 근무자 이름은 직원이 인트라넷 **설정**에서 넣는다. 경비실 태블릿에서 그 계정으로 로그인해 두면 된다.
