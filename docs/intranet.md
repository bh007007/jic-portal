# 인트라넷 (`apps/intranet`)

직원용 화면과 경비실 가드 태블릿이다. 디자인은 `docs/design/IntranetPenalty.dc.html`(I1 패널티 승인)과 `GuardTablet.dc.html`(I2 외출·귀가 가드 태블릿, 1180×820)을 따른다. 1차는 **로컬 개발 서버 전용**이다.

## 실행

```powershell
npm install
npm run intranet
```

http://127.0.0.1:5177 을 연다. 가드 태블릿은 http://127.0.0.1:5177/guard (외출·귀가 화면의 '가드 태블릿 열기'). 로컬에는 로그인이 없다(관리자 앱과 같다).

## 규칙

### 외출·귀가 (가드 태블릿)

- 재학생 명단(관리자 core의 '재학' 분류)에 있는 학생만 기록한다. 졸업생·입학 예정자는 "재학생 명단에 없는 번호입니다."
- 입력값에서 숫자만 쓴다. USB·블루투스 QR 스캐너가 카드키 QR을 읽어 학생번호 칸에 넣고 Enter를 보내면 바로 처리된다. 학생번호 칸에는 항상 커서가 있다.
- 외출: 이미 외출 중이면 거절한다(외출 시각을 보여 주고 귀가로 처리하라고 안내).
- 귀가: 외출 기록이 없어도 귀가는 남긴다. 통금 확인에 필요하기 때문이며, 목록에 '외출 기록 없음'으로 보인다.
- 설정에 근무자가 있으면 근무자를 골라야 기록된다. 이 기기에서 고른 캠퍼스·근무자·외출/귀가는 기기에 기억한다.

### 통금 판정

- 시각은 필리핀 시간(UTC+8) 기준이다. 저장은 ISO(UTC).
- 외출·귀가는 '밤' 단위로 묶는다. **오전 5시 전 기록은 전날 밤**이다(예: 11/8 01:10 귀가 → 11/7 밤).
- **승인된 외박이 있는 밤은 통금 위반이 아니다.** 외출 기록과 가드 태블릿에 '외박 허용 ~복귀일'로 보인다.
- 그 밖에 그날 밤 통금 시각(설정, 처음 값 23:00)보다 늦게 외출했거나, 늦게 귀가했거나, 통금이 지나도 귀가하지 않았으면 통금 위반이다. 근거 문장 예: `통금 23:00, 귀가 23:41`, `통금 23:00 이후 외출 23:20, 귀가 23:55`, `통금 23:00, 미귀가`, `통금 23:00, 귀가 01:30 (외출 기록 없음)`.

### 가드 리포트 (업체 eni, 기획안 incident_reports)

- 가드 태블릿의 '사건 리포트 작성'에서 학생번호(방금 처리한 학생이 미리 들어감), 종류, 내용(500자), 발생 시각(비우면 지금)을 받는다. 종류는 업체 포털과 같은 음주·폭력·무단외출·기타.
- 발생 시각이 지금보다 뒤면 전날로 본다(자정 넘어 쓰는 리포트). 재학생만, 설정에 근무자가 있으면 근무자를 골라야 등록된다.
- 등록하면 **패널티 승인 대기 후보가 바로 생긴다**(출처: 가드 리포트). 음주는 '음주', 폭력·무단외출·기타는 '기타'로 들어간다(점수표에 따로 없는 종류). 근거는 `가드 리포트(22:40): 음주 — 내용 앞 60자`, 발생일은 통금과 같은 '밤' 기준.
- 리포트는 고치거나 지우지 않는다. 잘못 쓴 리포트는 패널티를 반려한다(통금 후보 정리는 가드 리포트 패널티를 건드리지 않는다).

### 신청 처리 (결석·외박)

- 학생 앱이 쓰는 신청 데이터를 그대로 읽고 고친다. 모양과 규칙은 `apps/student/server/requests.ts` 한 곳이다.
- 대기 중인 신청만 승인·반려된다. 학생이 이미 취소한 건은 건너뛰고 몇 건을 건너뛰었는지 알려 준다.
- 처리 메모(300자)는 학생 앱 신청 상세에 '담당자 메모'로 보인다. 반려 사유를 적는다.
- 대기 목록은 날짜가 가까운 순(처리할 순서), 처리된 목록은 최근 처리 순이다. 메뉴에 대기 건수가 보인다.

### 내부 공지 (기획안 I10, 업체 게시판 → 내부 공지)

- 대상은 전체 또는 캠퍼스 하나. 캠퍼스로 보면 그 캠퍼스 공지와 전체 공지가 함께 보인다.
- 게시 종료일이 지나면 '지난 공지'로 넘어간다. 수정에서 종료일을 지난 날로 바꾸면 바로 내려간다. 삭제 기능은 두지 않았다.
- 직원이 공지를 열면 읽음(이름·시각)이 직원마다 한 번 남는다. 이름을 입력하지 않았으면 읽음이 남지 않는다. 메뉴와 홈에 이 직원이 안 읽은 게시 중 공지 수가 보인다.
- 작성·수정에는 오른쪽 위 직원 이름이 필요하다(상담 기록과 같다).

### 상담 기록·접근 기록 (기획안 I5, 권한·보안 '접근 기록')

- 목록·Student File·접근 기록에는 **제목만** 내보낸다. 내용은 상세에서만 보이고, 상세를 열 때마다 '열람'을 남긴다. 같은 직원이 같은 기록을 10초 안에 다시 열면(새로고침 등) 한 번으로 센다.
- 작성·수정·후속 조치 완료·되돌림도 남긴다. 접근 기록은 추가만 되고 고치거나 지울 수 없다. 상담 기록 삭제 기능은 두지 않았다.
- 검색은 학생·제목·작성자만 된다. 내용 검색은 사실상 열람이라 넣지 않았다.
- 후속 조치 기한이 있으면 '확인할 일'에 들어가고, 기한이 지나면 빨갛게 보인다. 메뉴에는 기한이 오늘이거나 지난 건수, 홈에는 열린 건수가 보인다. 기한을 바꾸면 다시 열린 상태가 된다.
- 처리자: 로컬에는 로그인이 없어 **오른쪽 위에 입력한 직원 이름**(브라우저에 저장)을 쓴다. 이름이 없으면 상담 기록을 열거나 쓸 수 없다. 배포에서는 로그인한 직원으로 바꾼다.
- 상담 분류(학업·생활 등)와 공개 범위는 정해지지 않아 만들지 않았다. 제목에 자유롭게 쓴다.

### 패널티

- 통금 위반은 외출 기록에서 **승인 대기 후보로 자동으로 올라간다**(출처: 외출 기록). 같은 외출 기록으로는 한 건만 생긴다.
- 승인 대기 중인 후보는 다시 계산한다. 미귀가였다가 귀가하면 근거가 바뀌고, 통금 시각을 늦추거나 그 밤의 외박을 승인해 더는 위반이 아니면 후보에서 빠진다. 승인·반려한 건은 바뀌지 않는다.
- 점수는 점수표에서 가져온다. **비어 있으면 '점수 미정'**으로 보이고, 그대로 승인하면 0점으로 센다. 승인할 때의 점수를 그 건에 남기므로, 나중에 점수표를 바꿔도 이미 승인한 점수는 그대로다.
- '승인 후 누적'은 그 학생의 승인된 점수 합계 + 이 건의 점수, 경고 단계는 점수표 기준으로 `- → 1단계`처럼 바뀌는 단계를 보여 준다. 기준이 비어 있으면 '기준 미정'.
- 위반 종류는 디자인의 4가지(무단결석, 통금 위반, 음주, 기타)다. 통금 위반은 외출 기록에서, 음주·기타는 가드 리포트에서 후보가 생긴다. 무단결석은 LMS 출석이 연결된 뒤 붙인다.

## 구조

```
apps/intranet/
├─ server/core.ts        /api/* 계산 (파일·네트워크 의존 없음)
├─ server/counseling.ts  상담 기록·접근 기록 (core 가 학생 이름 찾기만 넘겨 준다)
├─ server/notices.ts     내부 공지·읽음
├─ server/reports.ts     가드 리포트 종류·패널티 종류 연결
├─ server/core.test.ts   core 시험 (가짜 시계·메모리 저장소). 빌드할 때 함께 돈다
├─ server/localData.ts   로컬: Vite 플러그인, 파일 저장 (결석·외박 신청은 학생 앱 파일을 같이 연다)
└─ src/                  화면 (React + Vite + TypeScript)
```

- 학생·연수는 관리자 앱의 `createDb`(재학생 명단 `listEnrollments`, 이름 `studentDetail`)와 `loadDir`을 그대로 쓴다.
- 스타일은 관리자 앱과 같은 값을 `src/styles.css`에 복사해 두었다(공통 UI 패키지가 생기면 옮긴다).
- 시험: `npm --workspace apps/intranet run test`. 통금 판정 경계(통금 후 외출, 자정 넘어 귀가, 외출 기록 없는 귀가, 미귀가 후 귀가), 점수표 검증, 승인 점수 유지, 통금 변경 시 후보 정리, 외박 승인 시 후보 제외·외박 허용 표시, 결석·외박 승인·반려와 메모, Student File 목록·상세, 상담 기록(처리자 필수, 목록에 내용 없음, 내용 검색 안 됨, 열람 기록·10초 중복 제외, 수정·후속 조치, 필리핀 날짜 검색), 내부 공지(고정 순서, 캠퍼스 대상, 읽음 직원마다 1번, 안 읽은 수, 게시 종료), 가드 리포트(검증, 자정 넘은 발생 시각, 패널티 후보·종류 연결, 목록 검색), 귀국 일정(기본 기간, 미등록, 차량 요청) 등 109개 항목.

### 로컬 저장

결석·외박 신청은 학생 앱과 같은 `.local-db/student/` 파일을 쓴다. 상담 기록·접근 기록은 `counseling-<source>.ndjson`, `audit-<source>.ndjson`(실제 데이터로 실행하면 민감 정보). 가드 리포트는 `reports-<source>.ndjson`. 귀국 항공편은 학생 앱 파일(`.local-db/student/departures-<source>.ndjson`)을 같이 읽는다. 내부 공지는 학생 데이터와 상관없어 `notices.ndjson`, `notice-reads.ndjson` 하나씩. 나머지는 저장소 루트 `.local-db/intranet/`(Git 제외)에 `outings-<sample|extract>.ndjson`, `penalties-<sample|extract>.ndjson`, `settings.json`, `penalty-rules.json`을 쓴다. 실제 추출본으로 실행하면 학생 번호가 들어가므로 `data/`와 같이 다룬다.

## 배포 전에 필요한 것

1. **계정**: 직원은 `staff_users`(+ 역할별 권한, HANDOFF 6-4), 가드는 계정 방식 결정(근무자별 / 경비실 공용) 후 `is_guard()` 같은 새 함수. 처리자(`decidedBy`, 근무자)를 로그인 사용자로 채운다.
2. **테이블**: 기획안 데이터 모델의 `outings`, `penalty_rules`, `penalties`, `incident_reports`(가드 리포트)(그리고 `keycards`, `overnight_permissions`)를 `docs/collab.md` 데이터베이스 규칙대로 새 마이그레이션으로 만든다. 열은 `server/core.ts`의 `Outing`·`Penalty`·`PenaltyRules`, `server/reports.ts`의 `IncidentReport` 모양을 따른다(snake_case, `student_no`, `enrollment_id`).
3. **상담 기록 권한**: 기획안의 `counseling_notes`, `audit_logs`. 내용은 테이블을 직접 읽지 못하게 하고, 열람을 남기면서 내용을 돌려주는 서버 함수(security definer 또는 Workers)로만 읽는다. 접근 기록은 insert만 허용하고 update·delete는 막는다. 누가 어떤 학생의 상담 기록을 볼 수 있는지는 역할별 권한(HANDOFF 6-4)에서 정한다.
4. **내부 공지**: 기획안의 `internal_notices`와 읽음 테이블. 직원만 읽기, 작성·수정은 역할에 따라.
5. **미귀가 확인**: 지금은 화면을 열 때 계산한다. 배포에서는 통금 직후 Cloudflare Workers 크론으로 후보를 만든다.
6. **태블릿**: 경비실 태블릿에서 배포 주소를 연다(로컬 개발 서버는 이 PC에서만 열린다).

## 확인이 필요한 것

- 통금 시각(지금 23:00, 디자인 기준)과 캠퍼스·요일별 차이, 밤을 나누는 기준(오전 5시).
- 위반별 점수, 경고 단계 기준점, 점수 소멸 시점, 승인 권한(HANDOFF 7). 정해지면 점수표 화면에 입력하면 된다.
- 카드키 QR에 들어갈 내용(학생번호만인지, 카드 번호인지)과 태블릿 카메라로 직접 읽을지(지금은 스캐너 입력). 정해지면 `keycards`와 연결한다.
- 가드 리포트: 종류(음주·폭력·무단외출·기타)와 패널티 종류 연결(폭력·무단외출을 '기타'로 둘지, 점수표에 종류를 더할지), 사진 첨부가 필요한지.
- 학생 사진: 업체 포털 사진 이관 방식이 정해지면 '사진' 자리에 붙인다.
- 내부 공지: 부서·역할 단위 대상이 필요한지(직원·부서 데이터가 아직 없음), 첨부 파일, 로그인 때 띄우는 팝업 공지(업체 포털에 있음).
- 상담 기록: 누가 어떤 학생의 기록을 볼 수 있는지(담당·캠퍼스·역할), 상담 분류가 필요한지, 보관 기간, 학생·보호자 동의 문구(기획안 미결정 5번, 필리핀 개인정보보호법).
