# 역할별 권한표 (초안, 레오님 결정 #3)

원칙 C5의 9개 역할이 4개 포털에서 어느 화면을 읽고 쓰는지 정하는 표다. **초안이고 아직 코드에 넣지 않았다.** 지금은 아래 '지금 상태'대로 동작한다. 표를 확정하면 RLS와 메뉴 숨김을 이 표대로 바꾼다.

표기:
- **쓰기**: 읽고, 등록·수정·처리한다.
- **읽기**: 보기만 한다.
- **캠퍼스**: 맡은 캠퍼스만 본다(`user_roles.campus`, 빈칸이면 모든 캠퍼스).
- **본인**: 자기 것만 본다(학생 본인, 에이전시 자기 지점, 가드 자기 출입구).
- **-**: 화면을 열 수 없다.
- **?**: 결정이 필요하다(아래 '정할 것').

## 정할 것

1. **오피스의 회계**: 현지 비용·포인트를 오피스가 처리하면 오피스도 '쓰기'로 한다. 초안은 '읽기'(인보이스·입금 매칭은 관리자만 쓰기)다.
2. **마케팅 직원(본사)**: 9개 역할에 따로 없다. 오피스로 볼지, 관리자로 볼지, 역할을 하나 더 둘지 정한다. 초안은 오피스다.
3. **결석 신청 승인**(결정 #4): 매니저(L4)와 오피스 둘 다 할지 정한다. 초안은 둘 다이고, 같은 DB 함수(`decide_absence_requests`)를 쓴다.
4. **매니저의 패널티 승인**: 수업 관련 위반(무단결석 등)만 매니저가 승인할지 정한다. 점수표의 '승인 권한' 칸에 역할을 적는 방식으로 할 수 있다.
5. **강사·체커·스케줄러의 내부 공지**: 강사도 내부 공지를 보게 할지 정한다. 보게 하면 강사 포털에 공지 화면을 붙인다.
6. **체커의 성적 입력**: 체커가 시험 감독·점수 입력을 하는지 정한다. 초안은 '안 함'이다.

## 확정되면 바꿀 것

1. 직원도 `user_roles`에 역할(`office`·`admin`, 캠퍼스)을 넣는다. 관리자 포털 '사용자·권한' 화면에서 준다(#40).
2. `is_staff()`는 그대로 두고 역할 함수를 더한다. 예: 회계 표는 `has_role('admin')`, 기숙사 쓰기는 `has_role('office','admin')`.
3. `staff_campuses`(상담 범위)를 `user_roles.campus`로 합칠지 정한다. 합치면 캠퍼스를 한 곳에서 관리한다.
4. 메뉴에서 권한이 없는 화면을 숨긴다. '준비 중'인 화면은 지금처럼 이유와 함께 보인다.
5. 권한 시험(`supabase/tests/*`)에 역할별 경우를 더한다.
