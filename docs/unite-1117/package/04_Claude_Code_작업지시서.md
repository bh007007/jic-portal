# Claude Code 전달용 — JIC Partner Portal 콘텐츠·상담 UX 통합 개발 지시서

## 역할 / 목적

현재 운영 기준 코드는 `jic-portal` 저장소(`apps/partner`, `apps/admin`, 공통 `packages/quote` 등)입니다. **V74 시제품은 글 원문·이미지 배치·디자인 참고 소스**입니다. 시제품을 통째로 이식하거나 이미 완성된 계산/권한/DB를 대체하지 마세요.

이번 작업은 **페이지 메뉴 개편 + 상담모드 선택형 개선 + V74 글 콘텐츠 임시 이전 + 하나의 콘텐츠 원본으로 상세/요약 표시**입니다. **등록/승인/인보이스 신규 개발은 범위 제외**입니다.

### 입력 자료

1. `01_최종_사이트맵_프로세스.md` — 구조와 사용자 흐름(반드시 읽기)
2. `02_페이지별_화면설계.md` — 화면별 목적, 구성, 버튼 동작
3. `03_콘텐츠_이전_매핑표.md` — 시제품 콘텐츠 목적지와 검수
4. 원본 `01_전체구조_기능명세서.md`, `02_페이지별_콘텐츠_원문.md`, `03_상담기능_상세명세서.md`, `JIC_V74_추출.zip`
5. `JIC Partner Portal 개발 현황 분석.md` — 11/13 기준 코드 현황 기록(실제 최신 상태는 저장소에서 재확인)

### 중단/보존 조건 (반드시 준수)

- 현재 git 브랜치/배포 상태를 확인하고 작업 전 **백업 브랜치 또는 태그**를 남긴다.
- 먼저 전체 변경 계획과 파일 목록을 제시하고, **기존 기능을 훼손하지 않는 작은 PR**로 작업한다.
- 이미 업로드한 사진을 중복 업로드하지 않는다.
- 승인 가격표, 가격 계산 모듈, 추천 엔진의 현행 동작, 로그인/권한, 국가별 노출, 자료실 서명 URL을 유지한다.
- 상담의 학생 응답/견적 입력은 현재처럼 DB에 저장하지 않고 세션 메모리로만 유지한다(현재 원칙 변경 금지).
- 외부 에이전트에는 Draft 미노출. 개발/관리자 프리뷰만 임시 원문을 보여준다.
- 기존 상세 URL 및 딥링크는 유지하거나 안전한 redirect를 만든다.
- 운영 페이지에 시제품의 과거 가격·날짜·학생 통계·실제 여부 불분명한 수업 규칙을 무검수 게시하지 않는다.
- 새 메뉴를 만든다고 `/register`, `/students`, `/tuition` 등의 기존 경로를 삭제하지 않는다. 이번 메뉴에서만 비중을 조정한다.

## 작업 순서 (각 단계별 결과 보고 후 다음 진행)

### Phase 0 — 실제 코드 기준 재검증 / dry-run

- 문서 이후(11/13~현재) 커밋·배포 차이 확인.
- `apps/partner` 실제 메뉴, 상담 상태관리, 프리뷰 권한, 자료실, 코스 표시명, 3문항 레벨 테스트, 견적 연동 정책을 확인.
- 현재 DB 백업/상태 스냅샷, 이미 이전된 사진 자산 목록 확보.
- V74 원문 콘텐츠를 구간별 파싱하고 DB 레코드와 diff(`existing_same`, `existing_draft`, `missing`, `conflict`) 보고.
- 코스/캠퍼스 `course_id ↔ display_name ↔ quote_code ↔ campus_id` 대응표 제출.
- **이 단계에서는 쓰기·배포 금지**.

### Phase 1 — 관리자 콘텐츠 프리뷰와 임시 데이터

- 기존 콘텐츠 모델을 우선 재사용; 마이그레이션은 필요한 최소 컬럼만.
- V74 문장/표/FAQ/학생 하루/캠퍼스 소개 등을 원문이 보존되도록 **Draft로 import** (중복 없이 idempotent).
- 관리자가 '내부 미리보기'에서 임시 콘텐츠를 실제 레이아웃과 사진으로 확인할 수 있도록 구현.
- '미검수' 표시, 소스·원문·수정일, 누락/충돌 검수 리스트 제공.
- 외부 로그인 계정이 임시 콘텐츠를 못 보는지 RLS/서버 접근 시험.
- **현재 화면의 글이 나오지 않는 원인을 우선 진단**: 입력 누락인지, publish 필터인지, 국가/언어 조건인지, 콘텐츠 종류/placement 매칭 문제인지 각각 로깅하고 해결.

### Phase 2 — 네비게이션 및 대시보드

- `01` 사이트맵대로 **1단계 메뉴 정리**. 2단계는 학교·코스 허브/관련 페이지 탭에서 노출.
- 홈 업무 단추를 공실/견적/상담/자료 최상단으로, 아래 캠퍼스/업데이트.
- 기존 URL·직원/대표 권한·캠퍼스 필터·연락처/방문 접근 보존.
- 학교·코스 허브를 기존 상세 페이지에 연결하며 모든 V74 상세 콘텐츠의 목적지를 만든다.

### Phase 3 — 상담모드 개편 (엔진 재사용)

- 진입 시 `미선택`, `캠퍼스 선택`, `캠퍼스+코스 선택` 인식.
- `캠퍼스+코스`가 있으면 **선택 코스 설명으로 시작**, 추천 이유로 곧장 점프하지 않는다.
- 7개 자유 탭(코스 설명 / 목표·수준 / 선택 개선 / 증거·생활 / 수업 / 견적 / PDF) 제공. 탭은 강제 순서가 아니다.
- 선택 개선: 목표·학습량·기간 유연성·수준, 현재 선택+대안 최대 1, 대안 없음도 지원.
- 기존 3문항 간단 레벨 테스트 선택 사용. V74 5질문을 그대로 중복 구현하지 않는다.
- 기간 변경이 견적·최종 PDF에 반영. 규정 없는 혼합/캠퍼스 전환은 추천하지 않는다.
- 동일 `course_id`와 `content_id`에 요약 headline/benefit/evidence 연결; 숫자 정보는 승인 원천을 읽는다.
- 기존 PDF 및 통계, 상담 종료시 메모리 삭제 동작 유지.
- 내부 정보가 상담 화면/인쇄/PDF에 포함되지 않는지 자동 시험.

### Phase 4 — 공실·견적·JIC Play 연동

- 공실: 현재 외부 업체 포털 연결 상태 유지 + 상단 퀵검색 조건 폼. 데이터 미연동 상태에서 가용 좌석 결과를 생성하지 않는다.
- 견적: `packages/quote` 및 공통 `QuoteResultBlock` 재사용, 선택조건 prefill/동기화, 대표/직원 권한 확인.
- JIC Play: V74 추천 묶음의 **콘텐츠 분류/사용성**만 가져오고, 실재하는 영상/URL/권한으로 연결. 임시 QR 링크는 실제 공유 기능으로 오인되지 않게 처리.

### Phase 5 — QA / 출시 준비 분리

- 내부 프리뷰 스크린샷과 시제품(원문) 매핑, 페이지별 원문 누락 0을 검사.
- 대표/직원/비로그인 접근 권한, 국가별 노출, 직접 URL, 새 탭, PDF, 모바일, 기존 링크 회귀 테스트.
- 상담 시나리오 T01~T12 실행 기록 및 문제 목록 제출.
- **출시 승인 전** 콘텐츠 검수/가격·학사·일정 최신화/국가별 번역 검수. 미검수 콘텐츠는 계속 외부 비공개.

## 작업별 산출물 요구

1. `IMPLEMENTATION_PLAN.md`: 변경 범위, 영향 파일, DB 변경 여부, PR 순서, 위험/롤백.
2. `CONTENT_IMPORT_DIFF.csv`: 모든 시제품 원문과 현재 DB 비교, destination, 상태, source_key.
3. `COURSE_MAPPING.csv`: 코스명/캠퍼스/추천 규칙/견적 코드 대응.
4. `PAGE_CONTENT_QA.csv`: 각 화면별 원문 배치·미디어·프리뷰·외부게시 상태.
5. 변경 PR마다: 화면 캡처(Before/After), 기능 동작 검증, DB/RLS 영향, 테스트 결과.
6. `OPEN_DECISIONS.md`: 학사 정책/권한/코스명/V2.2/공실 연동처럼 사람이 결정해야 할 항목. 확정 전 임의 추정 금지.

## 완료 인정 기준

- 내부 프리뷰에서 콘텐츠 글이 실제로 보임(시제품 문장/표/카드 누락 없이 해당 자리에서 확인).
- 정식 에이전트 화면에는 승인 콘텐츠만 보임.
- 코스 결정 상태에서 상담 시작 시 해당 코스 **설명 화면**이 즉시 열림.
- 상담 입력 정보를 한 번만 넣고 코스/기간/견적/PDF에 전달함.
- 승인된 계산/권한/공통 미디어/기존 경로가 변경으로 깨지지 않음.
- 실시간 공실 검증이나 뉴스레터 발송 등 미구현 기능을 구현된 것처럼 표시하지 않음.

> 개발자에게: 바로 전체 구현을 시작하지 말고 **Phase 0 현황·영향·이관 diff를 먼저 제출**한 다음 작은 단위로 진행해주세요. 이는 기존 사이트를 지키기 위한 기술적 안전장치입니다.
