# JIC Partner Portal 콘텐츠 중심 통합 개편안 v1.0

기준: V74 시제품(2026-10-23 표기, 2026-11-17 추출), Claude Code 개발 현황 분석(기록 2026-11-13까지), 2026-11-17 대화 합의.

> 상태: **개발 전달용 제안안**. 운영 정책·콘텐츠 사실관계·실제 배포 여부의 승인 문서가 아님. **등록/승인/인보이스 신규 개발은 이번 범위에서 제외**. 기존 링크 및 기능은 삭제하지 않는다.

## A. 개편 목적과 고정 원칙

**목표**: 에이전트가 상담 중 필요한 정보를 빠르게 찾고, 학생에게 JIC를 설득력 있게 설명하고, 선택 조건을 반복 입력하지 않도록 한다.

1. 기존 `apps/partner` 및 `apps/admin`을 개발 기준으로 삼는다. V74의 순수 HTML 앱을 그대로 복제하거나 운영 시스템을 덮어쓰지 않는다.
2. 시제품의 **글 원문 전체를 이전 후보로 보존**하고, 일반 포털에는 상세 정보를, 상담모드에는 요약과 근거를 보여준다. 생략된 글도 아카이브에 보존한다.
3. 사진은 **이미 이관된 자산을 우선 재사용**한다. 중복 업로드 금지. 시제품 자산 중 실제 없는 파일은 누락 목록만 작성한다.
4. 가격·수업량·학사 규칙·공실 등의 사실 데이터는 단일 승인 원천에서만 노출. 시제품에 박혀 있는 숫자·금액은 복사하지 않는다.
5. 승인 전 콘텐츠도 **관리자 및 테스트 계정의 프리뷰에서는 채워진 화면으로 표시**한다. 외부 파트너에게 자동 게시하지 않는다.
6. 에이전트 전용정보(플레이북, 수수료, 계정, 학생 목록, 방문 처리 등)는 학생 공유 화면에 절대 포함하지 않는다.
7. 현재 상담 응답을 DB에 저장하지 않는 원칙을 유지. 상담 상태는 세션 내 공통으로 이어받고, 끝내면 초기화한다.
8. 화면 전환 시 캠퍼스/코스/기간/입학일/방 타입은 유효한 범위에서 유지. 조건이 바뀌면 연동 결과를 재검증한다.
9. 등록·승인 기능은 나중에 다루되, 기존 `/register` 외부 링크 및 향후 메뉴 확장 여지는 유지한다.
10. 기존 권한·국가별 노출·다국어·라우팅·자동시험을 삭제하거나 우회하지 않는다.

**메뉴 축소 ≠ 원본 페이지 삭제**. 아래 기존 주소는 유지하거나 새 허브에서 연결한다:
`/campuses/:id`, `/campuses/compare`, `/campuses/camp`, `/about/baguio`, `/about/why-jic`, `/about/teachers`, `/about/school`, `/courses`, `/courses/:id`, `/day`, `/life/calendar`, `/life/activities`, `/evidence`, `/playbook`, `/faq`, `/tuition`, `/register`, `/newsletter`, `/contacts`, `/visit`.

**권한 유지**: `/quote`, `/tuition`, `/visit`은 현재 지점 대표만 접근 가능. 상담·근거·학교정보는 직원도 접근. 직원의 견적 액션은 현재 문서 간 불일치이므로 기존 권한을 임의로 완화하지 말고 표시/이동 정책을 검증한다.

## D. 상담모드 새 진입 구조

### D1. 세 가지 시작 상태, **새 필수 7단계 절차가 아님**

1. **처음부터 찾기**: 캠퍼스/코스 미정 → 목표·중요 요소·수준·기간을 선택형 질문으로 확인 → 추천 1개+대안 최대 1개.
2. **캠퍼스만 선택**: 선택한 캠퍼스의 코스 안내에서 시작 → 학생 목적 확인 → 해당 캠퍼스 내 적합성 검토. 필요한 경우 캠퍼스 변경도 상담사가 허용할 때만 제시.
3. **캠퍼스+코스 선택**: **해당 코스 상세 설명 화면에서 즉시 시작** → 특징·수업·증거를 보여주고 '더 적합한 선택 검토'를 선택할 수 있게 한다. 이미 선택한 코스를 자동 추천 1위로 가장하지 않는다.

선택값(있다면): 캠퍼스, 코스, 단계/수업 구성, 영어 수준 또는 '모름', 학습 목적, 기간, 기간 변경 가능 여부, 입학일, 기숙사. 미정 필드는 물음표로 유지하고 필수 입력을 강요하지 않는다.

### D2. 자유 이동 탭 (상단 고정, **클릭 가능**)

`코스 설명 | 목표·수준 확인 | 선택 개선 | 증거·둘러보기 | 수업 구성 | 공실·견적 | 학습계획서`

- 기본 진입은 위 D1에 따라 다르다. 탭을 자유롭게 오가되, 선택이 없는 기능은 '필요 조건 선택'을 부드럽게 안내한다.
- 학생에게 보이는 화면에서 내부 메뉴·플레이북·가격 마진/수수료·관리자 콘텐츠를 렌더링하지 않는다.
- 상담 종료 시 결과/PDF 확인 안내 후 메모리 초기화; 학생 개인 정보는 DB 저장하지 않는다.

### D3. 코스 설명 → 선택 개선

- 기본 카드: 코스명, 1문장 핵심 메시지, 적합한 목표, 수업 구성 요약, 대표 증거 1~3건, `[자세히 보기]`.
- `[이 선택 유지]`와 `[더 적합한 구성 검토]`를 나란히 제공한다.
- 선택 개선 입력: 학생 목표 / 영어 수준(모름→기존 3문항 간단 테스트 선택) / 희망 학습량 / 선택 기간 / 기간 변경 가능 여부. 이미 존재하는 값은 재질문하지 않는다.
- 결과: **현재 선택** + **조건에 맞는 대안 최대 1개**. 근거 3개와 연결된 증거. 대안 없음도 정상 결과.
- 기간 조정: '현재 계획'과 '연장 검토안'을 나란히 비교. **A2→B2 = n주** 같은 보장 수치 금지. 기간 연장으로 추가되는 활동/반복/피드백을 설명. 연장안 비용은 실제 견적 모듈을 호출.
- 혼합/캠퍼스 전환: 현재 운영·가격 규칙이 허용하는 조합만 추천. `packages/quote`의 최소주수, 코스/숙소 합계, IELTS Guarantee 마지막 단계 규칙을 재사용; **V74의 minStage/minCross/OPTIMAL 초안 규칙을 승인 없이 이식 금지**.
- Speaking Starter/Pro/Master는 CEFR 레벨과 등치시키지 않고 말하기 과제의 깊이/성격으로 설명.

### D4. 영어 수준

- `알고 있음 → 수준 선택 / 잘 모름 → Claude Code 기존 3문항 테스트 / 건너뛰기`.
- 결과는 '참고용 간단 진단' 표시. 스피킹 실력 전반/입학 배정의 확정 결과처럼 표현 금지.
- V74에 테스트가 없으며 현재 Claude Code `/consult`에 3문항 테스트가 있으므로 **V74의 테스트를 복사하라는 지시 금지**.

## E. 빠른 업무: 공실과 견적

### E1. 공실 `/vacancy`
- 현재는 **업체 포털 링크**이다. 공실을 내부에서 실제 계산한다고 표시하지 않는다.
- 1차 UI: 페이지 상단에 `캠퍼스 / 입학일 / 기간 / 방 타입` 퀵검색 폼, 아래에 `업체 공식 공실 화면 열기` 및 기존 매트릭스에 대한 설명/연결. 검색 기능은 **공식 데이터 연동 전에는 '조건 정리 + 공식 화면 이동'**만 제공하며 가짜 가용 결과를 보여주지 않는다.
- 2차 데이터 연동 전제: 업체 공실은 단순 침대 수가 아닌 **기수별 방 목표 − 학생 − 예외**, 국가 목표, 시작·주별 마감이다. 연속 기간/방 배정 확인이 가능한지 확인한 뒤 설계. 독립 계산기 임의 구현 금지.
- 공실을 조건으로 선택한 경우 견적에 캠퍼스·입학일·기간·방 타입을 전달할 수 있도록 상태 인터페이스만 정의한다. '견적 생성=입실 확정' 표현 금지.

### E2. 견적 `/quote`
- 운영 기준은 승인 `price_books` + `packages/quote`; 새로운 가격 계산식 금지.
- 기존 혼합 캠퍼스·장기등록·프로모션·픽업·현지비용·견적 PDF 기능을 모두 유지한다.
- 상담모드 내 견적은 **새 탭으로 분리하지 않고** 동일 엔진·결과 블록을 상담 컨텍스트 안에서 읽기 전용 또는 모달/내부 단계로 표시하는 방안 우선. 권한 제약이 있는 경우 가격 노출 정책을 먼저 명확히 한다.
- 입력값 1회: 상담에서 기간 변경→견적 자동 업데이트→학습계획서 동일 기간, 반대 방향 변경도 일치하도록 한다.

## F. 콘텐츠 원본과 표출

- 단일 원본: `courses/campuses`, `partner_content_items`, media, `course_reasons`, 근거 자료, `price_books`, `recommendation_rules`.
- **일반 포털 상세**: 원문·도표·시설·수업 구성·학생의 하루·활동·상세 근거.
- **상담용 요약**: 같은 원본 ID를 참조하는 `headline(1문장)`, `benefits(최대3)`, `evidence_ids(1~3)` 등 표시 메타데이터만 추가. 승인된 운영 수치/표는 원본 필드를 렌더링한다.
- 임시 이관 텍스트는 관리자 검수 프리뷰에서 전체 노출. `Draft/Review/Approved/Published`는 기존 초안/게시/숨김 모델과 호환하도록 설계 검토 후 적용. **미승인 자료를 외부에 자동 공개하지 않는다**.
- 시제품 V74 가격·통계·레벨·8주 의무·환불·등록 절차·과거 날짜·신규 캠퍼스 상태는 반드시 검수 태그를 단다.

## G. 데이터 충돌·검수 필수 사항

1. 상담 규칙 현재 V2.1 → V2.2 개정 대기. UI 이동과 기준 데이터 교체를 동일 PR에 섞지 않는다.
2. V74에는 5질문 진단, Claude Code에는 5질문+3문항 레벨 확인. 공식 기준 하나로 통합하되 질문값 매핑표 작성.
3. 두 프로젝트의 캠퍼스/코스 표시명 다름. **공통 course_id + display_name + price_code** 대응표 우선.
4. 사진 148장은 이미 Claude Code로 이관되었다고 보고 중복 업로드하지 않는다. 위치(`PLACEMENTS`) 변경 매핑 필요.
5. 캠퍼스 상태·최근 공지·2026 일정·학생의 하루 가상 인물은 모두 표시 출처/기준일 구분.
6. 공실 업체 포털과 데이터 연동 범위 미확정. '실시간 공실 보유' 단정 금지.
7. 외부 에이전트와 내부 프리뷰 권한 분리; 기존 대표 전용 가격 권한 정책 유지.

## H. 개발 완료 검수 시나리오

- T01 대표 로그인 → 홈에서 공실/견적 1~2클릭 진입.
- T02 직원 로그인 → 권한 없는 가격/방문/내부정보 차단, 상담·학교·자료 정상 작동.
- T03 캠퍼스 미정 → 목표 입력 → 추천·대안 → 코스 설명 → 학습계획서.
- T04 Premium 선택/코스 미정 → Premium 코스만 먼저 노출 → 선택 개선.
- T05 Premium + Speaking Pro 선택 → **코스 설명 즉시 표시**, 학생 질문 강제하지 않음.
