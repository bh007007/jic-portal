## 공통 규칙

- **각 Phase가 끝나면 멈추고 보고**합니다. 기획 확인·승인 뒤 다음 Phase(CL-100). 승인된 결과는 내부 확인용으로 바로 게시(CL-081). 포털은 외부 비공개.
- **작은 PR**: 한 PR은 한 가지 변화. 화면 이동과 기준 데이터 교체(조건표 V2.2, 코스 이름 CL-069~074)는 **절대 같은 PR에 넣지 않습니다**(전달메모 3장).
- **백업**: Phase를 시작할 때 `main`에 태그 `pre-unite-phaseN`. DB를 쓰는 PR은 바로 전에 해당 표를 JSON으로 내보내 보관(개인정보 없는 콘텐츠 표만).
- **지키는 것**: 승인 가격 버전·`packages/quote`, 추천 계산(`consult/engine.ts`, 조건표 V2.1), 로그인·대표/직원 권한(`STAFF_PATHS`·DB 정책), 국가별 노출, 자료실 서명 주소, 상담 응답 비저장(P3), 기존 주소. 디자인은 지금 부품(CL-095).
- **시험**: 기존 시험(추천 92·메뉴 75·콘텐츠 59·추천 이유 13·학비표 42·견적 103·DB 권한 시험)은 모든 PR에서 통과. 구조가 바뀌는 PR은 시험을 같은 PR에서 고침.
- **되돌리기**: 코드 PR은 `git revert` + 재배포(Workers 자동 배포). DB PR은 마이그레이션마다 되돌리는 SQL을 PR 설명에 같이 적고, 이관 데이터는 `data.migration_batch`로 한 번에 지울 수 있게 함.

## Phase 1 — 내부 미리보기와 V74 글 초안 이관

목표: 직원이 실제 화면에서 V74 글(초안)을 모두 보고, 에이전시 계정에는 게시된 것만 보입니다(누락 0).

### PR 1-1 직원 전용 내부 미리보기

- 내용: JIC 직원으로 에이전시 포털을 열면 상단에 '미리보기: 초안 포함' 켜기/끄기. 켜면 화면이 초안·숨김까지 읽고, 초안 줄에 '초안 · 미검수' 표시와 출처(`data.source`)·원문 키(`data.source_key`)를 보입니다. 에이전시 계정에는 스위치가 없고 DB 정책이 게시만 줍니다.
- 영향 파일: `apps/partner/src/content.tsx`(loadItems에 미리보기 상태), `auth.tsx`(직원 여부는 이미 있음), `ui.tsx`(초안 표시), `Layout`(스위치), `content.test.ts`
- DB: 없음(직원은 이미 `partner_content_items_staff_all`로 전부 읽음).
- 시험: 콘텐츠 시험에 '미리보기 끔 = 게시만, 켬 = 초안 포함, 에이전시는 켜도 게시만'. DB 시험 `partner_content_rls.mjs`에 '에이전시는 초안 0건' 확인 추가.
- 위험: 초안이 에이전시에게 보임 → DB 정책이 막음(화면 스위치와 무관). 되돌리기: revert.

### PR 1-2 캠퍼스·코스 글을 초안으로 담을 자리 (마이그레이션)

- 왜: `campuses`·`course_contents`에는 공개 상태 칸이 없어 V74 글을 넣으면 **바로 에이전시에게 보입니다**. 초안으로 담을 자리가 필요합니다.
- 제안(D-22): `partner_content_items`에 종류 `campus_info`(캠퍼스 × 탭: 소개·기숙사·시설·생활·식사·지도 지점)와 `course_info`(코스 × 칸: 요약·대상·구성·성과·수업 리포트)를 추가합니다. 기존 공통 칸(국가·순서·언어·상태·업데이트일)을 그대로 씁니다. 화면은 게시된 `*_info`가 있으면 그것을, 없으면 지금 표를 읽습니다(이전 호환).
