# 통합 관리 앱 권한 구조 (안, CL-025)

**상태: 11/12 레오님이 4장 6가지를 정했다. 1단계(표·판단 함수, 기본값 = 지금 규칙)는 `20261112110000_permissions_foundation.sql`.** 2단계부터는 5장 순서대로 넣는다(`docs/collab.md` '공동 작업 방식').

- **근거**: CL-025(11/10) — 직원 화면은 하나의 통합 관리 앱, 권한은 **역할·캠퍼스·범위(보기·입력·승인)**로 정하고 **DB 권한 규칙으로 막는다**. **승인 권한은 메뉴 권한과 따로** 준다. Leo가 할 일: "관리자 앱을 통합 관리 앱의 기반으로 유지하고 메뉴 그룹별 권한 구조 설계".
- **출발점**: 11/9 승인된 역할별 권한표(`docs/roles.md`, 읽기·쓰기·캠퍼스)와 지금 코드의 메뉴(`docs/menus.md`). 이 안은 그 표를 새 틀(보기·입력·승인)로 옮긴 것이고, **누가 무엇을 하는지는 바꾸지 않는다.** 바뀌는 것은 '승인'을 따로 떼어 사람마다 줄 수 있게 하는 점이다.

## 1. 틀

| 요소 | 뜻 | 지금 | 안 |

DB에서는 세 가지 확인 함수로 모은다(이름은 안).
- `can_view(메뉴 그룹)`
- `can_input(메뉴 그룹, 캠퍼스)`
- `can_approve(승인 종류, 캠퍼스)`

정책(RLS)과 DB 함수가 이것만 부르게 하고, 지금 함수(`is_admin()` 등)는 옮기는 동안 이 함수를 부르는 얇은 함수로 남긴다. 화면은 같은 함수의 결과로 메뉴·입력 칸·승인 단추를 숨긴다. 숨기는 것은 편의일 뿐이고 막는 것은 DB다.

## 3. 승인 권한 (메뉴 권한과 따로)

승인은 '그 메뉴를 볼 수 있음'과 따로 사람마다 준다. 기본값은 역할에서 오되, 관리자가 사람별로 더하거나 뺄 수 있게 하는 안이다.

| 결석 신청 승인·반려 | 학생 결석 신청(L4) | 매니저·오피스·관리자(`decide_absence_requests`) | 매니저는 캠퍼스 | 같음 |
| 무단결석 패널티 승인 | 시스템 후보(L5·I4) | 매니저(캠퍼스)·오피스·관리자(`penalties_manager_decide`) | 매니저는 캠퍼스 | 같음 |

## 5. 넣는 순서 (승인 뒤)

1. 표와 확인 함수(`can_view`·`can_input`·`can_approve`)를 만든다. 지금 규칙과 같은 기본값을 넣어 **바뀌는 사람이 없게** 한다. 보안 규칙 시험(`security_lint.mjs`)과 역할 시험을 같이 고친다. — **11/12 준비(`20261112110000`), 센터장 역할 포함.**
2. 관리자 앱 메뉴를 `can_view`로 숨긴다(지금은 '사용자·권한'만 숨김).
3. 승인 단추와 승인 DB 함수를 `can_approve`로 바꾼다. 처음으로 범위가 좁아지는 승인은 담당과 같이 한다.
4. '사용자·권한' 화면에 사람별 승인 권한 칸을 붙인다. — **11/12 준비: '기초관리 › 권한표'**(탭 3개: 메뉴 권한·승인 기본값·사람별 승인). 결정 ⑥대로 표를 화면에서 고치고(관리자), 결정 ②대로 센터장이 자기 캠퍼스 사람별 승인을 다른 사람에게 준다. 관리자의 '사용자·권한' 입력과 '역할·승인 권한 주기'는 잠김 방지로 화면에서 고정. 센터장이 강사 포털 역할(강사·체커·스케줄러·매니저)을 주는 곳은 같은 화면의 '강사 포털 역할' 탭(11/12).
5. 인트라넷·강사 포털 화면을 관리자 앱 메뉴 그룹으로 옮기는 일(통합 관리 앱)은 이 권한 구조가 들어간 뒤, LMS 통합 결정과 함께 정한다.

## 6. 11/10 추가 결정 반영 (R-010)

기획 요청 R-010으로 Change Log 1110 추가분을 이 안에 넣는다. 정할 것 6개(4장)는 Day 3(직원용 화면 명세)에서 직원 메뉴와 함께 검토한다(Q-4). 승인 7종 범위 축소는 센터장 확인.

| 지점 직원 | 지점 대표가 만들고 정지한다(JIC 승인 없음) | 상담·자료·공지(1차), 등록·픽업(2차) | 인보이스·회계·커미션, 직원 관리, 다른 지점 |

- `agency_members` 한 행이 아이디다. 대표는 `role = 'owner'`, 직원은 `role = 'staff'` + `owner_id`(대표)로 대표 아래에 붙는다(11/10 구현, `20261110193000_agency_staff.sql`). 직원 아이디는 대표가 이메일을 등록하고 직원이 그 이메일로 가입·인증하면 생긴다(11/10 레오님 결정). 직원 화면은 CL-032에 적힌 그대로 상담·자료·공지(1차).
- 승인 권한 '에이전시 가입'(3장)은 **지점 대표 아이디에만** 쓴다. 직원 아이디는 대표가 관리하므로 JIC 승인 대상이 아니다.
